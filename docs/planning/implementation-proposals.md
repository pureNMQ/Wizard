状态：工程提案，2026-10-28 从原工作流草案迁移；不代表已实现，也不把项目选择当作引擎强制要求。

相关任务开始时，结合 UE5.4 本机 API、最小运行验证及现有代码决定采用方案，在票据或符合条件的 ADR 中记录结果。在已确认范围内的实现细化由 Codex 推进；玩法变更按规格的变更流程处理。

## 职责与状态归属

| 责任 | 建议起点 | 需要验证或落定的内容 | 任务 |
| --- | --- | --- | --- |
| 玩家持续状态 | PlayerState 持有 ASC、AttributeSet 与玩家物品状态；Character 作为 Avatar | Owner/Avatar、占有/初始化/重生顺序、幂等授予；ASC 放 Character 也是可选方案 | T02、T04、T09 |
| 角色与控制器 | Character 管移动和表现，Controller 接收输入并请求业务 | 角色重建后的上下文/输入绑定、鼠标瞄准与 UI 隔离 | T02、T03 |
| 物品域 | 小接口协调背包、装备位置和金币事务；装备适配层管理 GE Handle | 完整校验与一次提交、失败结果、实例身份、保存快照边界 | T04、T06、T07 |
| 商店 | 配置目录与交互入口复用玩家物品事务 | 价格和容量校验、批量数量、暂停中交易 | T07 |
| 敌人与挑战 | 敌人持自身 ASC；行为树调用 C++ 追击/攻击节点，挑战控制器组织波次（2026-10-29 已接入简单闭环，见 T09） | 两类行为、波次状态、死亡/掉落一次性处理与回营地 | T02、T09 |
| UI | C++ CommonUI 基类和事件绑定，Widget Blueprint 配置布局与样式 | UE5.4 输入路由、焦点、暂停、拖拽和关闭清理 | T02～T07 |
| 保存 | 有明确生命周期的保存服务与 USaveGame 快照 | 写入顺序、恢复校验、退出前完成和失败反馈 | T04、T08 |

单个运行时模块按功能目录起步；有实际依赖或编译隔离收益时再拆模块。具体类名与公开接口在首个实现任务中落定。

## 数据、输入与平衡初值

- 技能/物品定义可采用 Primary Data Asset，目录、掉落和波次可采用 Data Table 或组合配置；选择扫描和 Cook 方案时一并验证软引用。
- 物品运行时身份的具体类型与序列化表示在 T04 落定；配置定义与运行实例保持分离。
- 首版单个本地存档槽、版本字段、按变更版本排队的异步保存是候选方案；实际选择在 T08 通过写入顺序和恢复实验落定，T04 提前设计可序列化数据边界。
- B 背包仍为快捷键提案；2026-10-29 用户确认靠近营地 Alchemy 按 E 打开技能搭配，不使用 K。1234 为单次按下施放，物理键位保存在输入映射资产中，规则见规格 R01/R03～R08。
- 伤害公式及属性/价格/掉落/波次数值属于待审阅或试玩调整的内容初值；六技能的机制范围以规格为准，素材映射通过实际预览落定。
- CommonUI 与 Enhanced Input 的具体连接方式需在 UE5.4 做最小验证；启用插件不等于接入成功。

## 未决项进入任务的方式

在票据中写出候选、验证方法和采用结果。仅当未决项会改变已确认的玩家行为、范围或验收时才需要用户先确认；普通可逆的工程细化不因“提案”标签自动增加审批步骤。

## 已确认的 UI 层级约束（2026-10-29）

用户确认 UIRoot 固定为 HUD、Menu、Modal 三层，后续功能复用这三层，不新增层。HUD 承载常驻展示；Menu 承载背包、技能和商店等常规界面；Modal 承载暂停和确认弹窗。C++ 管理入口、生命周期与状态，Widget Blueprint 配置三层布局及样式。实现和实际验证证据以 [T02](../../.scratch/wizard-demo/issues/02-basic-combat.md) 为准。

玩家 HUD 聚合容器 WBP_CombatHUD 直接继承 CommonUserWidget，仅保存模块层级与布局，不承载业务逻辑。生命与魔力显示由 WBP_PlayerStatus 的 C++ 基类监听 GAS 属性事件；聚合容器和玩家状态模块各自职责独立。2026-10-29 用户确认移除旧目标生命和按键文本，玩家状态模块锚定屏幕左下角。
