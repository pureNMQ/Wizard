## 4. 目录和命名提案

项目自有内容集中到 `Content/Wizard/`，按 Maps、Blueprints、Data、UI、Audio、VFX 等功能组织；C++ 按对应业务职责组织。

第三方核心资产先保留原有资源路径与包内结构，记录实际使用的来源、版本及许可。需要重命名或迁移时使用 UE 资产工具维护引用，并清理、检查重定向器。

展示内容的归档保存在 Content 外的可恢复素材库或备份中，避免放入 Content/Archive 后继续作为项目资源参与扫描。仓库和打包中保留已选核心资源及完整依赖。

## 5. 执行顺序与完成条件

1. 建立可恢复素材备份及 Git/LFS 基线；当前尚未初始化 Git，不能把候选删除当作已经可随时撤销。
2. 对照清单再次检查当前默认地图、代码/配置路径、资产引用和配套文件，确认没有未保存的相关编辑。
3. 使用 UE 资产工具按展示地图及依赖组处理，保存每批操作清单，保持原始素材可恢复。
4. 按需要处理重定向器，重新检查保留资产的依赖，打开当前关卡并运行基础移动。
5. 导入本项目实际需要的恢复音效和物品图标，验证加载与播放/显示后再处理对应旧内容。
6. 最小战斗链路与六技能表现落定后，再清理默认角色、备用怪物、重复场景版本和未选特效。
7. 明确配置最终打包地图与必要资产规则，实际执行 Cook/打包验证；编辑器整理和打包范围分别验收。

完成条件：保留资源可加载、没有新增缺失引用、启动地图和原有基础操作正常、目标包能够 Cook，并且每批剔除内容均可恢复。第一轮清理不承担修改玩法或重写框架的职责。
