# 本地学习约定

## 存放与触发

每个功能交付后，结合实际改动更新 `.local-learning/learning-plan.md` 及相关学习资料。目录由 Git 忽略；读取已有计划后沿用其进度和记录，不重置已开展的内容。

- `lessons/`：先修概念、关键代码与调用路径。
- `assessments/`：独立练习、累计测试与复测题目。
- `solutions/`：答案、讲评与实际错误分析。
- `evidence/`：练习和实验的本地证据。

上述目录按实际需要创建。工程测试、复现脚本和交付所需的验证摘要进入仓库；个人答案和掌握度记录留在学习目录。

## 每次教学交付

1. 从本次游戏行为和验证结果开始，再讲 C++/UE 的必要先修概念。
2. 用实际代码标出输入、业务、状态、表现和界面的调用路径；适用时与 Unity/C# 对照，并说明差异。
3. 解释设计理由、替代方案和生命周期边界，区分引擎契约与项目选择。
4. 给出一个能独立完成的练习及验证方法。题目和答案分开，用户提交前不主动展示标准答案。
5. 根据实际提交记录提示、错误与待复测项；累计与间隔复测跟随已有学习计划安排。

任务票据只记录材料位置与交付情况，不复制个人测验内容。没有客观验证时标为未测试；实现完成、用户看过讲解和用户独立掌握是三种不同状态。
