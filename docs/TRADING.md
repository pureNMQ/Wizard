# 商店与交易

规则来源：[规格R03/R04/R13/R23～R25](../.scratch/wizard-demo/spec.md)、[T07](../.scratch/wizard-demo/issues/07-shop-and-trading.md)。本文件说明已实现的职责和配置；实际效果验收状态以票据为准。

## 入口与界面

当前地图`Shop_CampMerchant`是商人NPC，商店交互直接由自身承载；房屋与棚顶仅为原有布景，不移动也不绑定交互。`BP_WizardShop`配置BattleWizardPBR的`WizardSM`骨骼模型、`PBRMaskTintMat3Inst`材质、`ABP_Merchant`蓝图待机动画（Idle01Anim）、身体胶囊碰撞、`DA_CampShop`及`WBP_ShopMenu`。

商人站在房屋前(-1650,700)的地面，Actor中心Z=90，网格局部Z=-90；交互半径250cm，营地盒体范围(1500,1500,500)跟随NPC。靠近商人按既有E键打开，交互范围、遮挡与提示都以NPC自身为目标；打开和交易提交均重验距离、遮挡、存活、非挑战与营地范围。先前房屋交互和550cm半径已由用户本轮明确要求替代。

CommonUI复用Menu、Modal及集中暂停。左侧商品列表与全部/装备/药水分类，固定商品详情和购买入口；右侧仅20格背包与可交互出售悬浮窗。余额使用已有T_Gold图标。商品列表可滚动；没有属性或装备栏，没有新增常驻教学文案。

用户截图反馈后，商店面板收为1040×652：商品行图标/名称/价格分列，定宽购买按钮位于详情下方右侧，采用深色按钮与金色主操作。商店专用`WBP_ShopInventoryTile`复用原格子基类与布局，仅缩至80×80；普通背包格尺寸保持原样。2026-11-01用户确认T07完成，功能交付已接受，验收依据见票据。

买卖均打开既有数量Modal，标题为购买或出售。输入框/滑动条同步整数，取消或Esc不成交。购买上限取当前余额及完整背包接收能力，出售上限取选中堆叠；确认时重新校验。装备中的物品只能先卸到背包再售。

## 数据配置

- `UWizardShopCatalog::Products`配置定义引用与购买单价，`bInfiniteStock=true`。首版明确拒绝有限库存，不静默忽略。
- `UWizardItemDefinition::bTradable/SellPrice`配置可交易性与正整数售价。素材无需登记到目录即可出售；装备与药水复用同一出售路径。
- 同一目录定义ID不可重复，商品必须为合法、可交易的装备或药水。修改数量和价格不需要业务分支。
- 新增装备：创建合法定义，配置四槽之一、五属性加成、图标/法杖模型，加入目录与敌人掉落表即可。新增出售素材：创建Material定义、图标、堆叠上限及售价，加入掉落表即可，不加入商品目录。真实掉落→买卖→换装→存档演示在T08/T10完成。

## 事务与生命周期

`InventoryComponent`是物品权威，PlayerState仍持唯一金币余额。Buy/Sell先验证价格、数量、完整容量、版本及身份，以int64检查乘价和int32余额范围，然后同时写入背包和余额，再广播两个事件。受限friend仅用于这一原子提交边界；通知期间双方均拒绝写入重入。失败不提交，买卖不改变装备区，不重复施加装备GE。

`WizardShopMenuController`负责会话与冻结数量请求，Widget只展示及转发。请求携带SessionId、Revision、定义、价格，出售还冻结来源实例。确认重验场景权限、目录身份和报价；关闭解绑，旧会话与成功重放拒绝。数量Modal复用既有整数控件，回调消费一次并在取消/失活/销毁时清理。正常背包的拆分/丢弃继续使用原路径。

有效交易广播可作为T08自动保存触发点；本任务不实现USaveGame或声称落盘完成。持久快照与金币应在事件后统一读取，完整存档往返由T08验证。
