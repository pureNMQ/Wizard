## 3. 内容配置初值的处理

- 六个技能的名字、特效和动画先做实际预览，再锁定可演示版本。
- 每槽至少两件装备，属性、价格与图标来自定义数据；同一法杖模型允许用于不同配置，但 UI 需要能清楚区分。
- 出售素材至少准备足以演示不同定义与堆叠的配置。数量、名称与售价是待试玩调整的内容初值。
- 波次数量已确认三波；每波人数、间隔、敌人配比和奖励以配置初值开始，试玩后调整。
- UI 优先验证交互、信息可读性、暂停与拖拽，再做样式统一。
- 新物品、商店条目和掉落条目的数据驱动演示必须进入最终验收。

## 4. 验证矩阵

| 系统 | 关键检查 |
| --- | --- |
| GAS | 连续激活、资源不足、冷却、无效目标、中断、死亡、重复初始化 |
| Enhanced Input | 映射资产、实际操作、按下/持续/松开/取消、四槽搭配、角色重建后无重复绑定 |
| 背包与拖拽 | 守恒、非法数量、容量边界、合并溢出、取消、跨槽替换 |
| 掉落 | 图标、部分接收、背包满、金币入账、掉落素材出售、离开再进入 |
| 装备 | 错误槽位、卸下/替换、背包满、反复换装、最大生命夹取 |
| 交易 | 金币不足、容量不足、错误定义、错误数量、买卖后余额与物品一致 |
| 存档 | 多次变更、写入顺序、重启、缺失/错误定义、损坏或不兼容数据 |
| CommonUI | 嵌套返回、暂停时拖拽、焦点、输入穿透、连射状态、事件解绑 |
| 打包 | 软引用资源、地图、图标、输入配置、开发插件依赖、独立运行及存档 |

自动化覆盖重要业务接口和 GAS 效果；动画、图标可读性及实际输入交互通过编辑器/独立包验证。记录二者的覆盖范围，不用一个通过结果代替另一种检查。
